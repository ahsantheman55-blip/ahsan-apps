Purpose, chess parallel and status

Confirmed preference: Ahsan wants an ultimate algebra tutor in the same spirit as the chess teacher. The chess app puts a playable board first and gathers coaching under one Help button, with tap-only advice and a blunt intellectual coaching voice. The algebra equivalent should let him work independently once he is good enough, and put advice under Help rather than interrupting him.

Recommendation: treat the problem workspace as the “board”. Solving is the main activity. Help holds hints, worked examples, mistake recaps, progress, and deeper coaching. The tutor advises; it does not take over the pen.

This report gathers structured ideas and verified research. It is not a build plan with dates, and it does not start coding.

Core features

Recommendation — keep a small set of powerful tools rather than many tiny buttons:

  1. Problem workspace. One clear problem at a time, fully readable by VoiceOver. Show the original statement, the current working line, and a short step history the user can reread. Correctness checking of each submitted step or final answer.
  2. Step-by-step solving. Allow entry of intermediate lines (for example expand, collect like terms, divide both sides), not only a final boxed answer. This matches how algebra is actually done and helps memory by externalising working.
  3. Hints ladder under Help. Tap-requested levels: light nudge, name the principle, show the next move without full solution, then a full worked solution. Never dump the answer first.
  4. Worked examples. Short sermon-voiced walkthroughs of the same skill, not quizzes. Tell him what went wrong in similar mistakes and what a careful solver would do.
  5. Review and recap of recent mistakes. On request only: the last three or four error patterns (sign errors, lost brackets, wrong operation on both sides, incomplete factoring, and so on), with a blunt explanation and one recovery drill.
  6. Progress tracking. Quiet skill bars or mastery markers by topic. No cheerleading. Quiet confirmation when a skill is solid; blunt honesty when it is not.

Recommendation — Help submenu sketch (subject to Ahsan’s preference): Hint; Worked example; What went wrong (mistake recap); Compare my steps to a model solution; Topic map and progress; Speak the expression term by term; Syntax help for typing maths.

Accessibility for blind users

Confirmed preference: blind user is primary. The interface must work with VoiceOver on an iPhone 11. Audio-supported design is fine; audio-only without text equivalents is not.

Recommendation — structure:

  • Semantic headings, labelled buttons, one main landmark, skip link, logical focus order.
  • No information carried only by layout, colour, or a drawn equation image.
  • Every expression available as readable text and, where practical, as MathML for quality speech.
  • Reread controls for the problem, current line, full working, and last feedback.

Researched — speaking maths unambiguously:

  • MathSpeak quick tutorial (SeeWriteHear): verbose MathSpeak uses boundary words such as “start fraction … over … end fraction”, and “superscript” with “baseline” to return to the main line. That reduces ambiguity in nested fractions and powers.
  • ClearSpeak research (ETS, via DOI) and MathCAT’s default ClearSpeak style aim for classroom-like speech (“x to the fourth power”, “the fraction with numerator … and denominator …”), with verbosity options for unambiguous reading. MathCAT documents ClearSpeak as the default speech style and SimpleSpeak as a more concise alternative (MathCAT user guide).

Recommendation: default to unambiguous speech for algebra training (ClearSpeak verbose, or MathSpeak-style boundaries for nested work). Offer a shorter style later if Ahsan wants speed. Always announce brackets, fraction starts and ends, and exponent starts and ends when nesting is present. Example: “(2x + 3) / (x − 1)” should not be left as “2 x plus 3 slash x minus 1” without boundaries.

Recommendation — navigating inside an expression: support term-by-term and sub-expression navigation (whole expression, then left/right side of an equation, then terms, then factors). MathJax’s explorer and MathCAT navigation show that term-by-term exploration is a proven pattern for screen-reader maths (MathJax accessibility features; MathCAT overview).

Researched — braille: in the UK, Unified English Braille incorporates maths and science signs; RNIB states there is no longer a separate specialist maths code in the UK (RNIB specialist braille codes). Nemeth remains important in the US and in many tools. MathCAT and Desmos both support Nemeth and UEB maths braille on refreshable displays. Recommendation: design so a future braille path is possible (structured MathML or equivalent), but do not block a first web build on braille hardware testing.

Recommendation — avoid visual-only notation: no reliance on spatially aligned “balance” diagrams without a spoken equivalent; no unmarked colour highlighting of like terms; no screenshots of worksheets as the only problem source.

Progressive difficulty

Recommendation — a practical algebra ladder for a club-minded adult learner refreshing school algebra (adjust after Ahsan’s level check):

  1. Expressions: like terms, expanding brackets, simple factoring.
  2. Linear equations in one unknown, including with brackets and fractions.
  3. Linear inequalities and number-line meaning spoken in words.
  4. Simultaneous linear equations (elimination and substitution explained in speech).
  5. Quadratics: expanding, factoring, completing the square, quadratic formula, with careful speech for roots and discriminants.
  6. Algebraic fractions and rearranging formulae.
  7. Optional later: functions, exponentials, logs, sequences — only if wanted.

Recommendation — mastery checks: a short set of mixed problems per skill, done without hints. Mastery means recent independent success, not a single lucky answer. Failed items return to that skill’s worked examples and drills. The tutor may suggest the next topic under Help, but should not auto-advance in a way that yanks control away.

When the tutor steps in versus stays quiet

Confirmed preference from chess: tap-only coaching; nothing automatic. Essential action feedback (accepted step, rejected syntax, correct or incorrect final answer) is not coaching and should always be announced.

Recommendation — default quiet mode:

  • Advice, hints, recaps and worked examples appear only when Help is used.
  • No live nagging after every slip.

Recommendation — optional “watch my back” mode, off by default: after a repeated error pattern (for example three similar sign errors in one session), Help can show a badge or a single polite notice that a pattern was detected, still requiring a tap to hear the sermon. This mirrors the chess idea that the advisory layer steps in when the user is truly lost, without constant commentary.

Researched context: intelligent tutoring systems such as Carnegie Learning’s Cognitive Tutor / MATHia monitor skill mastery continuously and give just-in-time hints (MATHia product page; Cognitive Tutor research summarised by RAND). ASSISTments research compared scaffolding questions with on-demand hints; scaffolding can help, but some students found forced scaffolds frustrating (Scaffolding vs. Hints in the Assistment System (PDF)). Recommendation for Ahsan: prefer on-demand hints and optional scaffolding under Help, not forced multi-step interrogation after every mistake — that matches his chess preference and the “work independently once good enough” goal.

Recommendation — fading support: as mastery rises, the default hint ladder starts one rung higher (nudge rather than full next-step), and “What went wrong” becomes shorter. When struggling, the ladder deepens again. The voice stays didactic; it does not turn into cheerleading.

Input methods for one-finger touch typing

Confirmed context: one-finger typing on an iPhone touchscreen is slow and error-prone for dense symbols. Dictation often mangles algebra.

Recommendation — primary input: linear text syntax in a single field, for example 2x^2 + 3x = 5, (2x+3)/(x-1), sqrt(x+1). Announce a short syntax card under Help. Accept common variants (** or ^ for powers; optional implicit multiplication rules stated clearly).

Recommendation — compact custom maths keypad: a small set of VoiceOver-reachable buttons for common tokens (plus, minus, times, divide, equals, brackets, caret, fraction template, square root, x, y, undo, speak expression). Keep the keypad short so swipe exploration stays manageable. Do not require hunting through the full iOS symbols keyboard for every operator.

Recommendation — step entry versus whole-answer entry: both. Default to step entry for training; allow “submit final answer” for timed confidence checks later if wanted.

Recommendation — undo and syntax tolerance: always-available undo of the last token or last line; clear spoken parse errors (“I could not read the second closing bracket”); do not punish a correct mathematical idea for a missing asterisk if the parse is unambiguous. Dictation remains optional secondary input, never the only path.

Existing approaches worth studying

Only items checked for this report are listed. Each note separates what was verified from why it may matter.

  1. MathCAT — MathCAT site. Researched: open library converting MathML to speech, braille (including Nemeth and UEB Technical) and navigation; ClearSpeak default; built into NVDA 2026.1. Useful for speech-quality and navigation design ideas. Limitation for an iPhone web app: MathCAT is primarily an AT library (NVDA, JAWS, Orca, and others), not a drop-in iOS VoiceOver engine; a web app would more likely use MathML plus browser/MathJax speech patterns, or a server-side/WASM approach if pursued later.
  2. MathJax accessibility / Speech Rule Engine — MathJax accessibility docs. Researched: generates speech and braille labels, supports expression exploration term by term, works across screen readers via ARIA labels. Useful as a practical web rendering path for spoken algebra. Limitation: configuring styles and ensuring reliable VoiceOver behaviour on iOS still needs real-device testing.
  3. ClearSpeak and MathSpeak — ClearSpeak ETS paper DOI 10.1002/ets2.12103; MathSpeak tutorial SeeWriteHear. Researched: two established conventions for unambiguous maths speech. Useful as the speech style rulebook for the tutor. Limitation: defaults can still be ambiguous unless verbosity or boundary words are turned up.
  4. Desmos accessibility — Desmos accessibility introduction. Researched: screen-reader-aware equation reading, keyboard access, audio trace for graphs, Nemeth and UEB braille modes. Useful reference for expression editing and optional graph sonification later. Limitation: Desmos is a calculator/graphing environment, not an algebra teacher with sermon coaching; audio trace helps graphs more than equation solving pedagogy.
  5. Khan Academy — Khan Academy screen reader guidance. Researched: supports screen readers; recommends NVDA with Chrome and MathPlayer or MathCAT for equations; VoiceOver with Safari on iOS is listed. Useful as a content and practice-structure reference. Limitation: not built as a blunt personal coach under one Help button; equation access depends on the AT stack; Khan states it prioritises screen-reader cases over third-party read-aloud tools.
  6. Photomath / Mathway-style camera solvers. Researched limitation: these products are organised around photographing printed or handwritten problems. For a totally blind user, aiming a camera at ink is a poor primary workflow. Treat them as contrast cases (instant answers, visual capture) rather than models to copy. Prefer typed or structured input and teaching steps over “point phone at worksheet”.
  7. Carnegie Learning MATHia / Cognitive Tutor — MATHia; RAND brief on Cognitive Tutor Algebra I. Researched: skill-by-skill cognitive modelling, adaptive hints, mastery tracking; large-scale study found benefits emerging in the second year of school implementation for high schools. Useful ideas: knowledge tracing, hint ladders, mastery. Limitation: commercial classroom product; feedback model is more continuous than Ahsan’s tap-only preference; accessibility for VoiceOver-first mobile use is not established in the sources reviewed here.
  8. ASSISTments — ASSISTments site; scaffolding research PDF linked above. Researched: free practice platform with immediate feedback, hints and explanations; research tradition on hints versus scaffolding. Useful for hint design and mistake-driven practice. Limitation: teacher-paced school tool, not a personal sermon-voiced coach.
  9. Nemeth and UEB maths braille — RNIB UK note linked above; MathCAT and Desmos braille support. Researched: UK practice centres on UEB for maths; Nemeth remains widely supported in US tooling. Useful if Ahsan uses or later adds a braille display. Limitation: braille display ownership and preference are unknown; do not assume Nemeth fluency for a UK user.

Recommended first increment

Recommendation only — mirror the chess incremental approach:

  1. Accessible workspace: problem text, linear input, step list, VoiceOver-friendly controls, unambiguous speech for the current expression.
  2. Legal-or-correct checking for submitted steps and answers on a small linear-equation set.
  3. Help button with a three-rung hint ladder and one worked example type.
  4. Then layer mistake recap, progress, richer topics, and keypad polish.

Do not build until Ahsan confirms this direction and answers the open questions he cares about.
